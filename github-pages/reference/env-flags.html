Environment flags

yggdrasim_common/env_flags.py is the single source of truth for the YGGDRASIM_* runtime flags: each one declares its name, category, summary, accepted values, default, when a change takes effect, and where an override is stored. Three surfaces read that one registry, and so does the table at the bottom of this page:

  • the Universal GUI, Environment -> Configuration (/api/env_flags/list, /api/env_flags/{name}/set, /{name}/clear, /reset)
  • yggdrasim_common.env_flags itself, for anything that needs the contract in code

Which value wins

  1. The process environment. VAR=... yggdrasim ..., a shell export, or a CLI flag that sets the variable takes priority over everything else.
  2. A persisted override, applied at process entry for flags the environment leaves unset.
  3. The flag's own default, which is what the Default column describes.

apply_persisted_env_overrides() never overwrites a variable that is already set, so a command-line choice is not silently replaced by a stored one.

Persisted overrides do not reach every command

Only the launcher (yggdrasim, yggdrasim-gui, yggdrasim-desktop, yggdrasim-web-server) and the SCP11 live shell call apply_persisted_env_overrides() at startup. A standalone console script such as yggdrasim-scp03 or yggdrasim-card-bridge reads the process environment only. Export the variable in the shell -- or start from the launcher -- when a stored value has to apply to one of those.

Where an override is stored

Persistence File Used for
runtime root state/env_overrides.json under the runtime root Most flags.
home ~/.yggdrasim/env_overrides.json Flags that cannot live inside the runtime root, because selecting the root from inside it would be circular. Currently YGGDRASIM_RUNTIME_ROOT.
session only -- Never written. Export it in a shell profile to pin it across launches.

A corrupt overrides file is quarantined rather than deleted, and only registered flag names are read back.

Reading the table

  • Accepts -- the exact values the editors write. A toggle writes the on value and unsets for off, so a shell comparison against 1 stays valid.
  • Applies -- immediately means the running process picks the change up; next launch means the value is read once at startup.
  • Persistence -- the file an override lands in, per the table above.
  • (sensitive) -- the flag weakens a security posture (insecure TLS, demo keys, the quirks gate, disabling plugins), so the editors ask for confirmation before writing it.
